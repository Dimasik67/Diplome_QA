# Отчет о проведении тестирования мобильного приложения “В хосписе”

## *Цель* - беспечить проверку качества функционирования всех основных компонентов приложения, включая отображение актуальной информации, удобство навигации, полноту предоставляемых услуг и безопасность взаимодействия пользователей с приложением.

## *Объект тестирования* - мобильное приложение "В Хосписе". Приложение даёт функционал по работе с новостями хосписа и включает в себя:
- информацию о новостях и функционал для работы с ними;
- тематические цитаты;
- информацию о приложении.

## *Окружение* - тестирование проводится на физическом устройстве - Samsung Galaxy S20FE, модель SM-G780G/DSM, ОС Android 16, API 36

## *Этапы тестирования* 
1. Ручное тестирование приложения;
2. Составление чек-листа тестирования приложения;
3. Составление перечня тест-кейсов для автоматизированного тестирования приложения;
4. Автоматизация тестирования;
5. Формирование отчета о проведении тестирования.

## *Перечень используемых инструментов*
Основные инструменты:
**Android Studio** — официальная интегрированная среда разработки (IDE) для создания приложений под операционную систему Android. Поддерживает языки программирования Java, Kotlin и C++, включает широкий спектр инструментов для проектирования интерфейса, отладки приложения, тестирования производительности и управления версиями проектов. Благодаря встроенным возможностям эмулятора устройства возможно тестировать приложения прямо внутри среды, имитируя работу на разных версиях Android и типах устройств.
**JUnit4** — это фреймворк для модульного тестирования на языке Java, позволяющий писать автоматические тесты для отдельных компонентов программы. Широко применяется при разработке Android-приложений, т.к. позволяет проверять поведение классов, методов и модулей отдельно друг от друга.
**Java-17** в качестве языка написания автотестов - как одна из наиболее современных версий, обладающая более расширенным набором функций.
**Gradle** в качестве системы управления проектами - более гибкая платформа для написания автотестов.
**Git и GitHub** - системы хранения кода.
**Espresso** — фреймворк, инструмент функционального тестирования для Android-приложений. Предназначен для UI-тестирования и проверки взаимодействия пользователей с приложениями. Позволяет создавать автоматизированные сценарии, проверяя элементы графического интерфейса и функциональность приложения в целом.
**Charles** - сниффер, позволяет анализировать сетевые запросы мобильных приложений, в т.ч. проводить моделирование различных конфигураций сети (2G, 3G, 4G, Wi-Fi).
**Allure** - для составления отчетов о прохождении тестов.
Дополнительно:
**Нейросеть OpenCode ** - для проверки кода, проведения рефакторинга, написания кастомных классов (Helper’s, Matcher’s, Assert’s)

### *В ходе тестирования приложения был проверен следующий функционал*:
1. Страница авторизации;
2. Главная страница приложения;
3. Страница информации о приложении (политика конфиденциальности, пользовательское соглашение);
4. Тематические цитаты;
5. Страница новостей;
6. Работа фильтра на странице новостей;
7. Панель управления:
7.1. Создание новостей;
7.2. Сотрировка, редактирование, удаление новостей;
7.3. Фильтрация новостей на странице "Панель управления".

#### *Этап 1 - ручное тестирование*. 
**Всего проведено** - 140тестов, из них:
- **пройдено** - 118 (84,29%);
- **не пройдено** - 22 (15,71%).
В том числе было проведено тестирование поведения приложения при различных конфигурациях сети, устройства.

#### *Этап 2 - автоматизированное тестирование*
**Всего выполнено** - 52 тест-кейсов.

## *Покрытие кода тестами*
- **Покрыто** - 47 (90,38%);
- **Не покрыто** - 5 (9,62%);
**Причины** - некликабельные элементы, схожесть тестовых сценариев.

## *Результаты тестирования*:
Были выявлены ошибки в работе приложения, о чем были заведены соответствующие баг-репорты, оформленные в issue

## *Сработавшие риски*
- добавление незапланированных тестовых сценариев;
- сложности в поиске и определении `id` элементов.


## *Трудозатраты*:
**Всего** - 115 часов. Из них:
**Ручное тестирование** - 30 часов;
**Автоматизированное тестирование** - 80 часов. Время написания авто-тестов увеличено в связи с тем, что поиск селекторов проводился вручную. Некоторые объекты не имеют собственных `id` (в частности, иконки категорий новостей).
**Оформление результатов тестирования (составление отчета, заведение баг-репортов)** - 5 часов.

## *Общие рекомендации*:
1. Для обеспечения корректной работы приложения необходимо устранение всех обнаруженных дефектов.
2. Для дальнейшей поддержки автоматизаии тестирования и увеличения тестового покрытия *желательно* добавление `id` некоторым ключевым элементам.
