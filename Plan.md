# **План тестирования  мобильного приложения "В Хосписе"**

## **1. Цель**

Обеспечить проверку качества функционирования всех основных компонентов приложения, включая отображение актуальной информации, удобство навигации, полноту предоставляемых услуг и безопасность взаимодействия пользователей с приложением.

## **2. Объект тестирования**

Мобильное приложение "В Хосписе"
Приложение даёт функционал по работе с новостями хосписа и включает в себя:
- информацию о новостях и функционал для работы с ними;
- тематические цитаты;
- информацию о приложении.

## **3. Окружение

**Окружение для тестирования на ПК:**

- Ноутбук MacBook Pro;
- macOS Tahoe версия 26.5;

**Окружение для тестирования на мобильном устройстве:**

- Мобильное устройство Samsung Galaxy S20FE;
- Adroid version 13 TP1A.220624.014;
- One UI 5.1.

## **4. Этапы тестирования**
1. Ручное тестирование приложения;
2. Составление чек-листа тестирования приложения;
3. Составление перечня тест-кейсов для автоматизированного тестирования приложения;
4. Автоматизация тестирования;
5. Формирование отчета о проведении тестирования.

## **5. Виды тестирования**
1. *Функциональное тестирование* - проверка базовых функциональных возможностей приложения: создание, обновление новостей, работа с цитатами, просмотр информации о приложении.
2. *Юзабилити-тестирование* - тестирование удобства пользования мобильным устройством и взаимодействием с интерфейсами приложения.
3. *Производительность и нагрузка* - определение производительности приложения путём измерения времени отклика и потребления ресурсов системы (расход энергии, CPU и пр.).

## **6. Тестирование мобильного приложения "В Хосписе"**

### **6.1 Предусловия:**
- На компьютере пользователя установлена среда разработки Android Studio.
- Скачан и распанован архив с тестируемым приложением.
- Мобильное устройство подключено к компьютеру пользователя.
- Проведена сборка приложения в Android Studio.
- Приложение через Android Studio установлено на мобильное устройство.

### **6.2 Валидация данных:**
**Валидные данные пользователя:**
- валидный логин пользователя - login2;
- валидный пароль пользователя - password2;

**Валидные данные для поля "Дата" при фильтрации новостей:**
1. Поле дата заполняется в формате "ДД.ММ.ГГГГ".
2. Дата начала периода не должна быть позднее даты окончания периода.

**Валидные данные для поля "Категория" при фильтрации/создании новостей:**
1. Категория новостей выбирается из выпадающего списка или вводится вручную с клавиатуры мобильного устройства.
2. Валидные категории новосте:
- Объявление;
- День рождения;
- Зарплата;
- Профсоюз;
- Праздник;
- Массаж;
- Благодарность;
- Нужна помощь.

**Валидные данные для поля "Заголовок" при создании новостей:**
1. Поле "Заголовок" *должно* содержать буквенные символы, заглавные и строчные, допустим ввод на латинице и кириллице.
2. Поле "Заголовок" *может* содержать отдельные цифры или спец.симолы, эмодзи.
3. Поле "Заголовое" не должно содержать *только* цифры, спец.символы или эмодзи.

**Валидные данные для поля "Время" при создании новостей:**
1. Время создания новости может выставляться как "ползунком" на циферблате, так и вручную с клавиатуры устройства.
2. Ввод времени создания новости с клавиатуры производится в формате "ЧЧ:ММ".
3. Формат заполнения поля "Часы" - двузначное число от 00 до 23;
4. Формат заполнения поля "Минуты" - двузначное число от 00 до 59.

**Валидные данные для поля "Описание" при создании новостей:**
1. Поле "Описание" *должно* содержать буквенные символы, заглавные и строчные, допустив ввод на латинице и кириллице.
2. Поле "Описание" *может* содержать в отдельные цифры, спец.символы или эмодзи.
3. Поле "Описание" не должно содержать *только* цифры, спец.символы или эмодзи.

## **7. Перечень используемых инструментов**

**Android Studio** — официальная интегрированная среда разработки (IDE) для создания приложений под операционную систему Android. Поддерживает языки программирования Java, Kotlin и C++, включает широкий спектр инструментов для проектирования интерфейса, отладки приложения, тестирования производительности и управления версиями проектов. Благодаря встроенным возможностям эмулятора устройства возможно тестировать приложения прямо внутри среды, имитируя работу на разных версиях Android и типах устройств.
**JUnit4** — это фреймворк для модульного тестирования на языке Java, позволяющий писать автоматические тесты для отдельных компонентов программы. Широко применяется при разработке Android-приложений, т.к. позволяет проверять поведение классов, методов и модулей отдельно друг от друга.
**Java-11** в качестве языка написания автотестов - как одна из наиболее современных версий, обладающая более расширенным набором функций.
**Gradle** в качестве системы управления проектами - более гибкая платформа для написания автотестов.
**Git и GitHub** - системы хранения кода.
**Espresso** — фреймворк, инструмент функционального тестирования для Android-приложений. Предназначен для UI-тестирования и проверки взаимодействия пользователей с приложениями. Позволяет создавать автоматизированные сценарии, проверяя элементы графического интерфейса и функциональность приложения в целом.
**Charles** - сниффер, позволяет анализировать сетевые запросы мобильных приложений, в т.ч. проводить моделирование различных конфигураций сети (2G, 3G, 4G, Wi-Fi).
**Allure** - для составления отчетов о прохождении тестов.
